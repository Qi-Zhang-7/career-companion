# Settings 长期记忆前端测试说明（2026-08-28）

## 1. 记忆开关

1. 打开 Settings。
2. 关闭“允许新的记忆”。
3. 刷新页面，确认开关仍然关闭。
4. 在 DBeaver 的 `User.memoryEnabled` 中确认值为 `false`。
5. 再次开启，确认数据库恢复为 `true`。

关闭开关不会删除已有 Memory，只表示未来不应产生新的长期记忆候选。

## 2. 手动新增记忆

建议测试内容：

| 字段 | 测试值 |
|---|---|
| 记忆类型 | 工作模式 |
| 信息性质 | Observation · 观察 |
| 内容 | 在项目进度存在外部依赖时，我希望先说明依赖，再给出下一次同步节点。 |
| 重要程度 | 3 · 重要 |
| 敏感等级 | 普通 |

保存后应看到：

- 列表立即出现该记忆。
- 状态为“你已确认”。
- 来源为“用户手动添加”。
- 版本为 1。
- 刷新页面后仍然存在。

## 3. 查看来源

点击记忆右侧眼睛按钮：

- 查看类型、信息性质、确认状态、版本和更新时间。
- 手动添加的记忆显示“用户在 Settings 中手动添加并确认”。
- 未来从聊天形成的记忆会显示关联对话或消息证据。
- 未来通过 `MemoryLink` 关联人物、事件和成长主题后，也会显示关联实体。

## 4. 纠正、拒绝与删除

### 纠正

把测试记忆修改为：

```text
在项目进度存在外部依赖时，我会先说明已完成部分和依赖，再约定下一次同步节点。
```

保存后：

- `confirmationStatus` 变成 `USER_CORRECTED`。
- `version` 从 1 变为 2。
- 原有证据关系不会被删除。

### 拒绝

点击“拒绝这条记忆”后：

- 状态变为 `USER_REJECTED`。
- 记录仍保留，用于防止未来系统重复提出同一个错误记忆。
- 后续 AI 不应把它作为已确认事实使用。

### 删除

点击“删除这条记忆”后：

- 页面不再显示。
- `Memory.deletedAt` 写入删除时间。
- `Memory.status` 变成 `DELETED`。

## 5. 搜索和筛选

- 搜索“依赖”，应该只显示包含该词的记忆。
- 使用“全部类型”筛选器切换工作模式、人物、事件等类型。
- 搜索不修改数据库，只在当前页面过滤。

## 6. 数据安全边界

- 测试时不要写入真实客户姓名、手机号、账号、密码、密钥、合同金额或未公开项目数据。
- 手动添加的内容是用户主动确认，不需要 AI 再次推断。
- Inference 必须明确标为推测，不能作为事实使用。
- Memory 是个人记忆库，不等同于外部文档知识库。
