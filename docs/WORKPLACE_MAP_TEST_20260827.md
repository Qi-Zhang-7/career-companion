# Workplace Map 前端测试说明（2026-08-27）

## 已有演示人物

数据库当前包含：

- 张经理：项目经理，关联多个项目事件、四种人物信息和一条沟通策略。
- 老王：后端工程师，关联接口依赖事件和人物观察。
- 陈处：政府客户，关联需求变更事件。

默认优先展示关联真实事件最多的人物。

## 推测确认测试

打开张经理详情，找到：

```text
Inference · 推测
可能更容易接受结论先行、时间明确的汇报方式。
```

可以测试三种操作：

- “符合”：状态更新为“你已确认”。
- “部分符合，纠正”：修改表述后保存，状态更新为“你已纠正”。
- “不符合”：状态更新为“你已拒绝”，记录仍保留用于防止系统重复提出同一错误推测。

这三个操作都会直接更新 `PersonObservation.confirmationStatus`。

## 新增人物测试建议

可以添加一位不涉及真实隐私的演示人物：

| 字段 | 测试内容 |
|---|---|
| 人物称呼 / 别名 | 小周 |
| Role | 前端工程师 |
| 人物分组 | 开发 |
| 组织 / 项目别名 | 当前政务项目 |
| Relationship | 核心协作方 |
| 影响程度 | 3 |
| Relationship Summary | 负责报表前端展示，与我共同确认指标口径和接口字段。 |
| 策略适用情境 | 指标口径或接口字段发生变化时 |
| 沟通策略 | 先同步字段变化和影响页面，再共同确认调整顺序。 |
| 新增信息类型 | Fact · 事实 |
| 具体内容 | 负责当前项目的数据报表前端开发。 |

保存后检查：

1. 地图人数增加。
2. 点击“小周”能看到人物详情。
3. 刷新页面后仍然存在。
4. DBeaver 的 `Person`、`Relationship`、`PersonObservation`、`CommunicationStrategy` 中出现相应记录。

## 编辑和软删除测试

1. 点击人物详情右上角铅笔按钮。
2. 修改 Role、人物分组或沟通策略。
3. 保存并刷新，确认修改仍存在。
4. 对测试人物点击“从职场地图中移除”。
5. 确认后人物不会继续显示，但数据库 `Person.deletedAt` 会有时间值。

软删除不会直接抹除历史事件关系，便于未来保留复盘和成长证据链。

## 数据边界

- Fact 只记录可以核实的事实。
- Observation 记录具体、重复出现的行为。
- Inference 必须写成“可能”，并保留确认状态。
- User Feeling 只表达用户自己的感受。
- 不要把“强势”“控制欲强”“人品不好”等标签当成事实。
- 测试时使用人物和公司别名，不输入真实敏感资料。
